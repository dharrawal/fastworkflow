# 3.4.0 — result search

*This document is the pull-request description for the `observation-offloading`
branch.*

## What ships

**Observation offloading and the answer-time behaviours become the framework's
behaviour, for every workflow.** Say that plainly, because it is the change:
these were experiment switches, each default-off and turned on by one evaluation
runner, and they are now simply what a fastWorkflow tool agent does. There is no
`FW_OBSERVATION_OFFLOADING` to set, no `FW_AUTO_NAVIGATION`, no
`FW_ANSWER_REHYDRATION`, no `FW_ANSWER_COVERAGE`. A workflow that upgrades gets
all of it.

The programme behind it is `bd show ido-8ps`: twenty-odd measured experiments on
one pinned stress task and one neutral task, each compared to its immediate
predecessor and to a control, each accepted or reverted by a dated owner
decision. Every row is in
`evaluation/artifacts/result-search/leaderboard.md` in the IDO repository.

### The loop keeps a bounded trajectory and loses nothing

* **Canonical handles.** Every `execute_workflow_query` observation is printed
  with its own `O{n}` alias and, since `ido-8ps.13`, the context instance the
  command ran in: `Observation O42 (execute_workflow_query, in Account
  28c5aeb5… Alan Cooper)`. The agent no longer guesses ReAct step numbers, and a
  listing produced inside a context is readable as that context's without the
  reader being allowed to use history.
* **Eager archive.** Every execute observation is persisted under its alias
  before anything is offloaded, so an observation is searchable whether it is
  still inline or has been replaced by a label.
* **Compaction to a packed target.** An observation is replaced by its own
  offload label when the swap frees at least the minimum saving — a property of
  the swap, not of the observation, so a 300-byte fact is never traded for a
  400-byte pointer.
* **`search_memory`.** One question against one stored observation, answered by
  a small model, bounded to a presentation budget, and never spanning
  observations.
* **Segmented continuation.** When the iteration ceiling is reached the harness
  forces a replan over a skeleton of the whole trajectory — labels where the
  text is offloaded, never reconstructed — twice at most, so a turn is at most
  three segments.

### Listings became handles instead of walls of text

* **Result handles** (`fastworkflow.result_handles`): a listing command declares
  one alias, immutable stored pages, a serialisable source descriptor and a page
  size. The observation the agent sees is bounded; the rows that did not fit are
  in the store and the next cursor returns them.
* **Bounded paging** with short cursor tokens, an empty page as the stop
  condition and `countOnly` as the proof of completeness.
* **Result-page references** in command artifacts (`__fw_result_pages__`), so a
  declaration points at rows this store owns rather than smuggling a mutable
  listing through the turn record's artifact envelope.
* **Literal filters** over a handle, refused as *unsupported* rather than
  answered locally when the handle holds only part of its relation.

### Routing says where a command lives, and can go there

* **R1 known-name guard** (`ido-8ps.8`): a command name a *different* context
  owns is never answered by this context's classifier. The prediction declines,
  the parent walk runs, and the decline carries a hint naming the owning
  contexts. 69 silent misroutes across 31 stored runs is what this is for.
* **Auto-navigation** (`ido-8ps.9`): when the walk is exhausted and one context
  owns the name, the framework runs the entry command and then the original one,
  both through the ordinary command path with their own spans and observations.
  Entirely declaration-driven — `enter_command` / `enter_commands` on the context
  callback class — and a pure function of the utterance and the context model.
  A context whose entry command needs a parameter the utterance does not give
  produces a blocking clarification that lists candidates and chooses nothing.
* **R3 threshold separation** (`ido-8ps.25`): the tiny tier's resolve threshold
  and its ambiguity threshold were written from the same measurement, so the
  band between them was empty in all 18 trained contexts of the published
  router, 7 of them byte-identical. One writer now establishes a non-empty band
  where the artifacts are produced.

### The answer is written from the evidence

* **Answer rehydration** (`ido-8ps.18`): immediately before the extract call,
  and only there, the extractor gets its own copy of the trajectory with the
  evidence put back — offload labels become their archived observations, bounded
  listings gain their stored rows, pages are rehydrated through their listing.
  Bounded, most-recent-first, and what did not fit is named so the writer can
  report it unresolved instead of guessing.
* **Coverage statement** (`ido-8ps.22` / `.23` / `.24`): the extract input is
  prefixed with a deterministic statement of what the run never retrieved and
  what it did, built by regex and substring test from the request and the turn's
  own stores. No model chooses anything and nothing is invented.
* **Roster nudge** (`ido-8ps.27`): a `finish` action taken while named people of
  the request were never the subject of any command becomes a bounded note and
  the loop continues — once per turn, never on exhaustion, never an `ask_user`
  round.
* **Evidence sentence** (`ido-8ps.28`): the block states, per subject the run
  made the subject of a command, which *other* named items of the request appear
  in that subject's own observations. Positive half only: what a subject's
  evidence lacks is never stated, because a bounded portrait would make that a
  false absence.
* **Attribution check** (`fastworkflow.answer_attribution`): the same question
  asked backwards, offline, as a judgement instrument over a finished answer.

### Identity and budgets

* **Workflow fingerprint scope rule v2**: a `benchmarks/` tree at the workflow
  root and the runtime observability store leave the content hash. The corpus a
  workflow is *measured with* moves when the measurements move, and on the tree
  that forced the decision five of six benchmark files were git-ignored — so the
  declared identity could not be reproduced from a clean clone, which is the one
  property this hash exists to have.
* **A refresh that rewrites nothing is not a change**: `workflow_content_hash`
  is content-only, so a regeneration that rewrites byte-identical command files
  with new mtimes leaves the workflow's declared identity where it was — unlike
  the legacy source fingerprint beside it, which keys on path plus
  `(size, mtime_ns)` and is *supposed* to move. The two coexist and must not be
  substituted for one another.
* **Context-window budgets** (`fastworkflow.context_budget`, new in this
  release): ONE input — the model's context window in tokens — and every byte
  budget a fixed fraction of it. See
  [`docs/context_budget.md`](../context_budget.md).

### Two correctness fixes this PR ships

* **`ido-8ps.29`** — a result-handle page fetched under a different context was
  stamped with *that* context's subject clause. An agent that opened Christopher
  Hubbard's identity and then re-paged Alan Cooper's entitlement listing got
  Cooper's rows recorded as Hubbard's evidence; the evidence sentence stated
  three rights as Hubbard's that ground truth gives him none of, and the
  attribution check called the pair SUPPORTED for the same reason. A `$0`
  offline replay over the ten stored evidence-pinned and roster-pinned attempts
  found **90 of 106 page observations across 8 of 10 attempts** carrying a
  clause that disagrees with their handle's declaration. The clause now follows
  the handle's declaring subject, found by walking `parent_alias` to the root; a
  declaring handle with no recorded clause *drops* the dispatch-time stamp
  rather than keeping a wrong subject.
* **`ido-8ps.30`** — `react.py` never passed `report.unavailable` to
  `answer_coverage.post_check`, so the attempted-vs-never-attempted split
  recorded `unavailable_total = 0` in every run ever measured. One argument; it
  changes a measure and no behaviour.

## Migration notes

### Removed environment variables

Every one of these was an experiment switch. The behaviour each guarded is now
unconditional; there is nothing to set.

| Removed | What replaces it |
|---|---|
| `FW_OBSERVATION_OFFLOADING` | nothing — `build_tool_agent` always returns a `StructuredContinuationReAct` with `search_memory` in its tools |
| `FW_AUTO_NAVIGATION` | the `enter_command` / `enter_commands` declaration on a context callback class. A workflow that declares nothing gets exactly the declaration-and-hint behaviour the flag's off position pinned |
| `FW_AUTO_NAVIGATION_CANDIDATE_STEPS`, `FW_AUTO_NAVIGATION_CANDIDATE_MAX` | the module constants `auto_navigation.CANDIDATE_STEPS` (3) and `CANDIDATE_MAX` (10) |
| `FW_ANSWER_REHYDRATION` | nothing — rehydration is what the extract step does. A run with nothing offloaded and nothing paged rehydrates nothing |
| `FW_ANSWER_COVERAGE`, `FW_ROSTER_NUDGE`, `FW_ANSWER_EVIDENCE` | nothing. Each behaviour is silent when it has nothing to say, which is what "off" used to mean in practice |
| `FW_MAX_FORCED_REPLANS` | the module constant `observation_offloading.continuation.MAX_FORCED_REPLANS` (2, therefore 3 segments) |
| `FW_OFFLOAD_HANDLE_ARCHIVE` | nothing — the handle archive always lives beside the workflow's own observability database (`<state root>/workflows/<workflow>/observability.sqlite3.offload-handles.sqlite3`) |
| `FW_EAGER_ARTIFACT_VALIDATION` | nothing — the unserializable-artifact check is unconditional. It still only warns; it becomes a hard rejection at v3.0 |
| `FW_OBS_MAX_ATTR_BYTES` | the constant `fastworkflow.tracing.MAX_ATTR_BYTES` (16,384). It caps a database row, not a model prompt, so it was never a context budget. `observability_config()` still reports the key, because provenance records the value in effect |

Setting a removed name has no effect and raises nothing. If your deployment
exports one, delete the line.

`FW_OFFLOAD_EVENTS` is **kept**. It is a destination, not a switch: offloading,
search and answer-time events are always recorded in-process, and this names a
JSONL file a copy is appended to. It is how the evaluation harness reads every
measure in this programme.

### The byte budgets now have one input

`FW_TRAJECTORY_MAX_BYTES`, `FW_ANSWER_REHYDRATION_MAX_BYTES`,
`FW_RESULT_PAGE_MAX_BYTES`, `FW_SEARCH_ANSWER_MAX_BYTES`,
`FW_OFFLOAD_HOT_MAX_BYTES`, `FW_RESULT_HANDLE_HOT_MAX_BYTES` and
`FW_OFFLOAD_MIN_SAVING_BYTES` all still work, and are now **tuning overrides**
rather than the interface. Unset, each is a fixed fraction of the model's
context window, resolved from `FW_MODEL_CONTEXT_TOKENS`, else the `LLM_AGENT`
model's `litellm` `max_input_tokens`, else a documented 131,072-token fallback.

The fractions are calibrated so that a 131,072-token window —
`cerebras/gpt-oss-120b`, the main agent model of every accepted run — reproduces
this programme's pinned values exactly: 28,000 / 250,000 / 3,072 / 3,072 /
262,144 / 262,144 / 1,024. **A deployment on that class of model needs no change
at all.** A deployment on a 32k model gets budgets a quarter of the size without
touching anything. One table, one provenance call: see
[`docs/context_budget.md`](../context_budget.md).

One behavioural difference worth knowing: these overrides are now read from the
workflow's `fastworkflow.env` *before* the process environment. Before this
release only `os.environ` was consulted, so a value written into a workflow's
own env file silently had no effect.

### v1 workflow fingerprints are incomparable

`WORKFLOW_SCOPE_RULE_VERSION` moved 1 → 2. A fingerprint declared under v1 is
reported as **`incomparable`**, not as stale: those trees did not drift, their
digests answered a question the selection no longer asks. Re-declare the
fingerprint against the current tree; there is no migration to run.

### The router needs a retrain

Two independent reasons:

* The intent classifier's **signal version** moved: `classifier_signal_version`
  `r3` is written by this release's pipeline, and a router trained before it
  does not carry the statistics the new thresholds are computed from.
* **R3 threshold separation** changes how `threshold.json` and
  `tiny_ambiguous_threshold.json` are written — `write_ambiguity_thresholds` is
  now the single writer for both and refuses to publish a collapsed pair. An
  existing router's two files are very likely equal or inverted (all 18 contexts
  of the last published IDO router were), and they are not repaired in place.

Retrain with `fastworkflow train`. Expect more DistilBERT calls and more
clarification turns; that cost is deliberate and was priced in the offline
replay on `ido-8ps.25`.

### `top_p` is gone from synthetic utterance generation

`generate_utterances_for_personas` sends `temperature` only. Current Bedrock
Claude models reject `temperature` and `top_p` together outright —
"`temperature` and `top_p` cannot both be specified for this model" — which made
every utterance-generation call a hard `BadRequestError` and blocked training
entirely. If you were relying on the nucleus setting, it was never reaching the
model.

### Span contracts

`fw.nlu.intent` moved v2 → v3: `auto_navigation_enabled` left the span with the
flag it recorded. A consumer that reads it should drop the key; a consumer that
switched on it has nothing to switch on, because the behaviour is unconditional.
