Old spellings, and what to write instead.

Older workflows, and older notes, use spellings the framework no longer accepts. Each row is one of them, the spelling that replaces it, and what you see if you keep the old one. Most fail when the workflow loads (fastworkflow run_cli, fastworkflow train and the server report it, naming the file); a few fail only when the line runs, and a few are ignored or only warned about. What a load error stops follows one rule, below. The idiom pages teach the new spellings; this table is the only place the old ones are listed.

Load errors: one rule, and the removed spellings

A mistake inside one command file fails that command only. The file does not parse or import, it defines both ResponseGenerator and PlanGenerator, or any check of its classes, fields, phases, steps or declarations fails (an old spelling from this page, a from_command_output that does not resolve, a call cycle, a facts field of another type, a ui hint that is not valid, a __call__ that does not take three arguments, a @descends_to target that is no context or whose parents name neither the command's context nor one it inherits, an approval_template that cannot be filled, a PlanGenerator that inherits another command's). That command does not load (a planning command is not matched, and running an execution command fails with its load error). The rest of the workflow loads, except a planning command whose step runs that command, which fails too with a step runs 'find_book', which does not load: see its own problem. fastworkflow run_cli, fastworkflow train (which stops), the server and fastworkflow command preview --check list it as one line, <command>: <file>: <message>, saying what to write instead. Nothing about a command is only logged while the command still loads, except the rows of the table below marked ignored or warned about.

A mistake in something the whole workflow shares stops the workflow, with one message that names the file: a context's inherits or parents (a name that is no context, with the context it probably meant; a name given twice; a context that inherits itself, or bases that lead back to it; a value that is not a list of string literals, an empty list, a declaration assigned twice or inherited from a Python base class), the removed _commands/context_inheritance_model.json, a context folder that holds no command file and inherits none, a context class file _<Context>.py that does not import, uses a removed spelling, has a public member that is no hook, writes get_parent without parents or parents without get_parent, or declares parents with occupiable = False, a class Context in a _*.py of a context folder other than _<Context>.py, a startup_action.json that names no command or a command that does not load, or has a misspelt key, a _workflow.py that does not import, defines no class Context, gives Context a public member that is no workflow setting or uses a removed spelling, a _split.py, any other underscore .py file or folder of _commands/ or a context folder (helper modules live in _commands/_shared/), a _skills/ folder, and no local model with no remote key. fastworkflow run_cli prints it and exits 1, and the server does not start (its process exits non-zero). One more startup problem is not a file's: a command with no Signature runs only as the startup action, so when nothing names one (no startup_action.json, no --startup_action or --startup_command) fastworkflow run_cli prints "has no Signature, so it runs only as the workflow's startup action, and nothing names it" and exits 1; the server only logs it, because a session may pass its own startup action.

Some mistakes show only when the line runs. The run-time rows of the table below fail there; in a workflow with a root, a context with no _<Context>.py or no get_parent, for a record that is not the root, raises MissingGetParentError on the first climb (with no root it means "go to the global commands", see the enclosing record), and so does a get_parent that returns a record of a context its parents do not name (nor a context that inherits one); and a command that moves workflow.record onto a record whose class is no context, onto a context its @descends_to does not declare, or, with a root, onto such a record, fails when it returns (see move onto a record).
