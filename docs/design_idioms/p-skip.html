A phase that does not run

Some work in a planning command only makes sense sometimes. Read a member's loans only when the request asks for them. Open the member only when the search found one. This page shows the three ways to say "not always", and which one to pick.

A quick vocabulary. A planning command is a command whose body is a plan (see a plan in place of a body). Each public method of its PlanGenerator is a phase: it returns a list of steps, the commands to run (see a step the code runs). What a phase found is its facts, which later phases receive as a parameter named after it (see what a phase hands on).

Pick by what decides it:

  • An input decides. List the phases in __phases__(self, input). The framework decides a call's phases from it before the first phase of that call runs, and runs only the phases it returns, in that order; it calls the method more than once (to build the template, for the run, and on resume), so make it depend on input alone. Without it, every phase runs.
  • What an earlier phase found decides. Write an ordinary if in the phase and return []. The framework calls the phase method once, when the phase is reached, with the real facts. An empty list means the phase is skipped.
  • Only the meaning of the request can decide. Wrap the step in when(condition, step). Code never judges the condition. See the second example.

A phase that returned [] is passed as None to every later phase and to __result__ (see the answer, in code). A phase that __phases__ left out is passed as None to __result__ only; a later phase that reads it keeps the parameter's default, and a parameter with no default is a load error, so write member=None for any phase __phases__ can leave out. In both cases test the parameter before reading the facts, and write if not member: rather than if member is None:. A facts model is always true, so not member means exactly "that phase did not run", and the template sees the test. A phase with no return annotation fills no facts, so its parameter is None even when it ran: test only an annotated phase this way. An is None test is invisible to the template: the planner and the preview show that step with no "only when" note. The shipped member_report.py below still uses is None, so its preview shows loans and notes with no note about member.

What you see when it runs. On a copy of the library example, fastworkflow command run-code library Library/member_report --input '{"member": "Nobody"}' runs the command with no model and prints Phase member: skipped (its method returned []), then the answer No member is named Nobody. With "loans": true for a member who exists, the loans phase runs; without it, the phase is not in the run at all. The preview (fastworkflow command preview) lists the phases with when each runs: member "only when find.member_uids", loans "only when loans = true".

Why the agent still understands the if: before the run, the planner is shown a template of the plan, built by calling each phase with stand-in facts. Every test on a stand-in fact reads as true, and the step is written with a note, so the template reads open_member with the uid of the <member> match (only when find.member_uids).

when() writes the step as the line only when the request asks what the member has borrowed, list_member_loans (full list). Code runs the steps before it and stops there, because it cannot tell whether the condition holds. What happens next depends on the session:

  • With an agent model (LLM_AGENT set), the agent reads the condition against the request and runs the step or skips it.
  • With no agent model (LLM_AGENT unset), when the inner step is one code can run and someone is there to answer, the command pauses with a yes-or-no question (question kind phase_step): "That step runs only when ... Does that hold? Reply yes to run ... now, or no to skip it". Yes runs the inner step by code, no skips it, and the command carries on either way. cancel stops the command at that step. When nobody can answer, or code cannot run the inner step, the command stops there and the turn reports what ran and the step it did not. The question is asked only on the plan path of an attended turn: a planning command run with a "/" message in no-agent mode stops instead of asking, and so does one called by another planning command or run under a framework command.

Two beginner mistakes:

  • Gating on a bool input with return [] inside a phase that hands on a command's Output. The template is built for both values of the bool, and for False the phase runs nothing, so the command does not load (the rest of the workflow does) and fastworkflow command preview --check fails: "phase 'loans' hands on list_member_loans's Output, but none of its steps runs list_member_loans". Put input decisions in __phases__.
  • Using when() for something code already knows, such as an input or a fact. The agent spends a step on it, and with no agent model the user is asked a question the code could have answered. Write an if instead.

See also shared phases, which also uses __phases__.
