Planning step helpers

The functions a planning command's phases use to write their steps, all imported from fastworkflow.planning (see a plan in place of a body). A phase returns a list of steps; each helper below writes one step, or a phrase inside the answer. A plain string is a step too: one a model carries out. A plain string written exactly like a command step (a command name and key=value pairs) is run by code as run() would run it; write run() instead.

HelperWhat it writesNotes
run(command, *, named=None, all_pages=False, **inputs)a step that runs command, which code runs itself when every required value is given (see a step the code runs)inputs are the command's own Input field names, checked when the files load; a None value is left out. named= opens the row of a listing with a cell equal to the whole name, else the listing's only row whatever its name (see the row a listing named); with a concrete id input also given, named= is dropped and the id is used. all_pages=True reads every page (see every page of a list). The two cannot be combined, and no Input may have a field called named or all_pages.
when(condition, step)the step only when <condition>, <step>Only a model, or a person asked yes or no, decides the condition. A person is asked only on an attended turn of the agent path with no agent model, outside a nested planning call; on a "/" turn, under run-code or with nobody to answer, code stops at the step. When the input or the facts decide it, write an if in the phase instead (see a phase that does not run).
do_not_run(command)the step do not run <command>Code passes over it; the agent reads it as an instruction to leave that command alone. The command name is checked when the files load, as a run() step's is: a misspelled one fails the load ("a step names 'find_bok', which is not a command of the workflow").
@phase(over=, max_items=, noun=, bind=, until=, optional=, output=)a decorator on a phase method, not a stepover runs the phase once per item, at most max_items (10 by default), with noun naming the items in the cap note, bind saying each item is a record its steps open, and until a function of the facts so far that stops the items (see once per item); optional=True lets the job go on when the phase fails; output= is a function of input alone that picks the facts type, in place of a return annotation (a fixed facts type is the return annotation). Any option may be a function of input alone, decided when the call is planned. Any other option name is a TypeError. max_items, bind, until or noun without over, a bind that is not a bool, and an over path that ends on one value fail the load.
count(number, noun, plural=None)1 copy, 3 copies; the plural is noun + "s" unless you give oneUse it in steps and in __result__ rather than your own number == 1 test: in the preview every fact is a stand-in, and the helper keeps it readable.
count_and_names_read(names, total, noun, same=None, plural=None)2 borrowers (Ann Lee, Raj Patel)none (0 borrowers) when the list is empty; 3 borrowers, none of them read when no name was read; 5 borrowers (Ann Lee, Raj Patel; 2 of 5 shown) when fewer rows were read than total. Pass the command's total, not len(names). same=("<what>", items) names a list the answer already stated in full: when names holds exactly those items, more than one and all of them read, it writes 2 borrowers (the same <what>) instead of repeating them.
ANSWER_BY_MODELa value __result__ returns, not a stepLeaves the answer to a model, exactly as when there is no __result__, on a command that declares no Output; on one that declares an Output it fails the call. With no agent model the call ends as a stop whose answer code writes (see the answer, in code).
a plain stringa step for the agent, such as "choose the book the request means"Code stops at it. A line that starts with one of a fixed list of 32 answer words ("say", "report", "compare", "note", "verify", "include" and others) is taken as being about the answer, and code passes over it, so a real instruction that happens to start with one of them is passed over too. A negation word before a command name also makes code pass over the step. A run() value that holds a condition word is written in quotes so it is not read as a condition (see a step the code runs).

fastworkflow.planning also re-exports the command decorators descends_to, user_approval_for_execution and UserApproval (see move onto a record, ask before it runs), the field option types (FieldOptions and its parts, for type checking a json_schema_extra dict), and run_code, which runs one call with no model as fastworkflow command run-code does. @writes is imported from fastworkflow (see a command that changes data).
